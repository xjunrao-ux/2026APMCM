# 第三题的程序运行思路

运行入口是 [run_q3.py](run_q3.py) 的 `main()`。程序从一次群体回放出发，依次回答四个问题：自然声和控制声的响应率相差多少？情境、声型、距离和群体大小与响应有什么关系？具体出现哪种行为组合？企鹅群多久开始响应？

入口先调用 R，再把 R 整理的每次回放交给 Python。`design()` 把实验条件变成数字，`fit()` 用实测行为估计参数，`predict()` 把给定条件代入模型，得到概率、时间和强度。

## 1. 读入 Data02：一行是一次回放，两行是一对实验

[R 入口](code1_baseline.R) 读取 [Data02 原始表](../题目与要求/date/Data02_AfricanPenguins_playbacks_data.csv)，直接执行比赛附件 Code1 中的 `case_when()` 和分组计数语句。它保留 278 次回放的 40 个原始字段，增加一列 `ResponseType`。Python 用原表核对所有行和字段，再用三项行为标记独立重算一遍组合。以 `expID=2` 为例，同一群 3 只企鹅正在赶路，两次播放距离都是 100 米。[R 导出的逐次数据](results/r_analysis_data.csv) · [R 分组频数](results/r_baseline_counts.csv)

| 回放 | 实际总体响应 | 首次鸣叫 | 首次抬头 | 首次靠近 |
|---|---:|---:|---:|---:|
| 双声型自然叫声 `tv` | 1 | 第 6 秒 | 第 10 秒 | 第 23 秒 |
| 控制声 `control` | 0 | 窗内未观察到 | 窗内未观察到 | 窗内未观察到 |

**一次实验的响应起点由观测确定。** 播放开始记为第 0 秒，群里第一只企鹅开始某种行为的时刻就是该行为的潜伏期。若问这条记录中最早的任意响应，答案是第 6 秒；第三题的预测表分别保留三种行为的时间。抬头这一列尤其容易混淆：本次 `HeadsUpLatency=10` 表示第 10 秒才开始，`HeadsUpDuration=8` 表示抬头行为持续了 8 秒。[原研究的观测定义及 60 秒观察窗](https://ore.eu/article/view/1538/version/2510)

全表有 90 对实验在两次播放时距离发生了变化，因此计算时保留每行自己的距离。三种目标行为是否发生，以各自的 `YesNo` 标记为准。逐次回放表从标为有响应的行为中取最小潜伏期，写入 `first_observed_s`；同秒最先发生的行为全部保存在 `first_behaviors`。有效的 0 秒原样保留，三项标记都为零时两列留空。筛选 `expID=2` 即可对照上表。对标记为零却填有潜伏期的记录，程序保留原值并另做敏感性分析。[逐次回放表](results/q3_trial_responses.csv) · [数据审计结果](results/q3_data_audit.md)

## 2. 数出总体差异，再用回归解释四个因素

**先数实测结果。** 按 `Type` 分组，统计 `ResponseYesNo=1` 的记录，自然声是 90/139，控制声是 18/139。按 `expID` 对齐后，有 74 对仅自然声引起响应，2 对仅控制声引起响应。`paired_tests()` 用这两个数做配对 McNemar 精确检验。

**再估计给定条件下的响应概率。** 输出只有“有／无”两种，输入有 `CallType`、`Context`、`Distance`、`Npenguins` 四个因素，因此这里用多因素二元 Logistic 回归。`select()` 先按实验编号分五折比较候选模型，同一对回放始终进同一折。本次选中包含“声型 × 情境”交互项的模型，允许同一种叫声在赶路和搜寻时有不同效果。

在 [models.py](models.py) 里，可沿着下面两行追踪一次预测：

```python
overall = logistic(z, d.ResponseYesNo.to_numpy(), w)  # fit()：学习系数
p = expit(z @ gate)                                  # predict()：系数和输入相乘，再转成概率
```

`z` 的每一行是一组实验条件。对 `expID=2` 的自然声记录，声型 `tv` 和情境 `commuting` 的指示值都是 1，距离输入为 `(100−80)/50=0.4`，群体大小输入为 `(3−8)/10=−0.5`。`logistic()` 根据 278 个实际的 0/1 答案调整系数，让发生过的结果尽可能获得较高概率，同时用弱岭惩罚稳定估计。

学到系数后，这条自然声记录的加权得分为 **1.477**，经 `expit` 换算得到 **81.4%**。配对控制声对应得分为 **−1.693**，换算得到 **15.5%**。这两个数是该条件下的拟合概率；原表记录的是当次实际发生的 1 和 0。考察距离或群体大小的作用时，也可以固定其余条件，只改变想研究的因素，再比较两次预测相差多少个百分点。

## 3. 从“有响应”走到“哪一种行为组合”

在比较四种声型之前，还可以看情境如何影响自然声与对照的差距。程序让每种情境都使用同一份实测距离和群体规模分布，再分别估算三类自然声和控制声的概率。三类自然声等权平均后，相对控制声的总体响应差在赶路时为 43.81 个百分点，在搜寻时为 72.63 个百分点，在进食后为 39.40 个百分点。各情境差值均附配对区间。[调整后的情境对比](results/q3_context_contrasts.csv)

H 表示抬头，V 表示鸣叫，A 表示靠近。每次回放落入八种互斥结果之一：`000`、`H`、`V`、`A`、`HV`、`HA`、`VA`、`HVA`。例如 `HV` 表示在观察窗内出现抬头和鸣叫，且未记录到靠近；两种行为可以先后发生。

第一阶段用全部 278 次回放估计任一目标行为出现的概率 (p)。审计表明，Data02 的“至少一种目标行为发生”与 `ResponseYesNo` 逐行一致，所以代码直接复用上一步系数，即 `gate = overall`。第二阶段用 108 次有响应的回放拟合七分类回归，得到已响应时各组合的条件概率 (q_k)。两个阶段在 `predict()` 里相接：

```python
p = expit(z @ gate)                              # 任意目标行为出现的概率
q = softmax(combo_design(x) @ classes, axis=1)   # 已有行为时，七种组合各占多少
combos = np.column_stack([1-p, p[:, None]*q])    # 无行为概率 + 七个非空组合概率
```

对 `expID=2` 自然声这一行，模型预测任意响应概率约 **81.4%**，已响应时三种行为都出现的概率约 **16.6%**。相乘得到单次回放发生 `HVA` 的概率约 **13.5%**。这次实测恰好属于 `HVA`。

**怎样判断某种声音是否提高特定组合概率？** 程序保留同一批 278 行的情境、距离和企鹅数，分别将声音设成 `control`、`flat`、`mod`、`tv`，用同一个模型预测。先在每一行计算 (p q_k)，再对相同声音的 278 个预测求平均。以 `HV` 为例，`flat` 的调整概率是 **27.57%**，控制声是 **0.42%**；按未舍入值相减，差值为 **+27.15 个百分点**，点态 95% 区间为 **[15.34, 37.64]**。这个区间支持 `flat` 下的 `HV` 概率升高。整组组合的分布是否变化，另用实验对内置换检验。[声型对比结果](results/q3_contrasts.csv)

## 4. 从概率走到首次响应时间（60 秒截断两部分模型）

首次响应时间分两部分相乘，且两部分都严格限定在 60 秒观察窗内：

1. **取出发生率。** 把八种组合中含 H 的四项概率相加，即 `P(H) + P(HA) + P(HV) + P(HVA)`，得到 60 秒内抬头的概率 p。超过 60 秒仍未抬头就是“无反应”，概率为 1−p，不再分配“之后才抬头”的概率。
2. **拟合截断对数正态。** `timing()` 只用 60 秒内真实抬头的 68 次 `HeadsUpLatency` 拟合截断对数正态：密度按 F(60) 归一化为 f(t)/F(60)，t ∈ (0, 60]。记录为 0 秒的 9 次抬头按首个半秒 F(0.5)/F(60) 的区间似然处理。
3. **累计曲线与反求时间。** 截至第 t 秒的累计发生概率 = p × F(t)/F(60)：t=0 时为 0、t=60 时恰为 p，从不超过 p，也不外推到 60 秒之后。发生者中位数即 F(t)/F(60)=0.5 的解。综合情境时 `integrate_context()` 按赶路 65/139、搜寻 38/139、进食后 36/139 混合三条曲线，再求混合后响应者的中位数。

**题设例子：8 只企鹅、100 米、播放 flat。** 下表来自上述抬头曲线，已按三种情境的实测比例综合。

| 播放后时间 | 全部回放中预计已抬头 | 60 秒内会抬头的回放中预计已抬头 |
|---|---:|---:|
| 1 秒 | 10.51% | 25.20% |
| 1.5 秒 | 17.81% | 42.69% |
| 1.75 秒 | 20.85% | 49.99% |
| **约 1.7505 秒（反求的中位数）** | **20.86%** | **50.00%** |
| 2 秒 | 23.49% | 56.32% |
| 60 秒 | 41.72% | 100.00% |

程序要找的目标是 **41.72% ÷ 2 ≈ 20.86%**。用二分法在 0 到 60 秒间查找，全体回放的累计抬头概率在约 **1.7505 秒**达到目标。固定时点的累计曲线列出两个分母：`p_event_by_t` 对全部回放计算，`p_by_t_given_event` 对窗内会出现该行为的回放计算。每个固定时点均有配对重抽样区间。某声型没有该行为的实测事件时，条件曲线留空，窗内发生概率保留模型估计并标注事件数。这里数的是回放。要估算一群 8 只企鹅中具体有几只抬头，还需知道群内响应个体的比例。[分时点累计概率表](results/q3_latency_curves.csv)

题设的 **8 只**来自 `Npenguins` 的中位数。拟合时使用所有群体各自的实测数量，制作预测表时才固定为 8，再交叉取三种自然声与 50、100、150 米。控制声也作为参照输出。接近仅有 23 次事件，因此其发生率随条件变化，发生后的时间合并估计。控制声的 139 次回放均未观察到接近，表中相应条件潜伏期留空。[代表条件预测表](results/q3_latency_predictions.csv)

## 5. 怎样核验预测和原始记录

潜伏期表的 `p_event_60` 是窗内发生概率，`median_if_event_s` 是发生者中位时间，`rmst_60_s` 是限制在 60 秒窗口内的平均等待时间，即 RMST = 60(1−p) + p·E[T | T≤60]，未响应的试次贡献完整的 60 秒。要核对数据支持，看 `n_exact` 和 `events_exact`。例如上面的 flat 综合情境在 8 只、100 米处仅有 1 条完全匹配记录，当次没有抬头；41.72% 是模型借助全部实验估计的结果。观察窗内未出现行为，不能据此判断企鹅是否感知到声音。

代码还单独输出响应**强度**。程序先估计指标取正值的概率，再乘以正值时的平均强度。抬头使用持续秒数，鸣叫使用播放后次数并控制播放前次数，接近的正持续时间取 23 次事件的合并均值。[强度预测表](results/q3_intensity_predictions.csv)

为了计算区间，程序按 `expID` 有放回地抽取 139 对实验，重新拟合和预测 499 次，取百分位数形成点态 95% 区间。性能评估采用嵌套分组五折。外层留出整对实验，在每个外层训练集内部再分五折选择总体响应结构和正鸣叫的分布，然后对外层留出实验预测。最终报告和预测表用全数据选模并拟合。性能数字属于内部验证。代码还比较了含实验随机截距的总体响应模型，以及含右删失的单分布时间模型。[逐行折外预测](results/grouped_oof.csv) · [模型诊断](results/q3_model_diagnostics.md)

**补充三怎样与自己的模型比较？** 第一层核对同一模型的参数。R 按 Code1 的选择重拟抬头持续时间的 hurdle 负二项、播放后鸣叫次数的 hurdle Poisson 和是否接近的 Bernoulli 模型，保留原先验、交互项和随机截距。三个模型都含情境、声型、距离和群体大小。前两个模型另用声型预测指标取零的概率；鸣叫次数模型还控制播放前鸣叫数。

第二层才比较自己的预测。固定声型、距离、情境、群体大小，鸣叫次数模型再固定播放前次数，分别计算“抬头时长大于 0”“播放后鸣叫次数大于 0”“60 秒内发生接近”的概率。尤其注意，播放后鸣叫次数大于零也可能是播放前已有的鸣叫活动。八类组合中含 V 的概率以 `VocalYesNo` 为准。三种事件各有 36 个条件，可以在表中逐行核对 R 和 Python 的估计以及各自的区间。补充三使用相同回放数据，独立实验上的预测性能仍待检验。[同条件的两模型对照](results/q3_code1_comparison.csv)

**补充四怎样与行为预测比较？** 在同一种声型内，沿 50、100、150 米看声学相似度和行为概率各自怎样变化。行为概率按三种实测情境的占比综合，条件中位时间按响应概率混合分布后求得。声学实验与回放实验只共享声型和距离；该表可以解释距离趋势，无法据此识别某一次响应是否由信号衰减引起。

## 在 VS Code 里复现

在 `problem3` 目录打开 PowerShell 终端。本机可用的解释器是 `D:\Python\python.exe`。Python 使用 NumPy、pandas 和 SciPy。R 使用 dplyr、brms、rstan、posterior 及相应 C++ 工具链。提取补充三的表格使用 `pdftotext`。第二问的 results 目录应包含 `gam_predictions.csv` 和 `supplementary4_check.csv`。

```powershell
& 'D:\Python\python.exe' run_q3.py
& 'D:\Python\python.exe' verify_exports.py
```

默认 R 拟合沿用作者设置，4 条链，每链 20,000 次迭代，含 5,000 次预热。核验程序流程可使用 `run_q3.py --stan-profile short`，每链 2,000 次迭代，含 1,000 次预热。拟合缓存按原始文件校验值、R 包版本和采样设置区分；更换设置会重新采样。可用 `--rscript` 指定 Rscript，用 `--q2-results` 指定第二问结果目录。主模型默认仍按实验配对重抽样 499 次。
